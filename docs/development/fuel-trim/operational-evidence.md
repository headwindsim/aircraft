# Operational evidence and remaining limits

Checked September 11, 2026. This is a simulation implementation record, not an A330-941 FCOM or a declaration of compliance. Public evidence does not establish every behavior of the targeted Honeywell P5A standard.

| Implemented behavior | Evidence and applicability | Limit |
| --- | --- | --- |
| Takeoff speed ordering and minimum-margin checks | [Airbus, Control your speed at take-off, July 2014](https://safetyfirst.airbus.com/control-your-speed-at-take-off/?airbus-iframe=true&airbus-post=2153): V1 <= VR, VR >= 1.05 VMCA, V2 >= 1.10 VMCA and V2 >= 1.13 VS1g. [Airbus TOS article, January 2020](https://safetyfirst.airbus.com/takeoff-surveillance-monitoring-functions/?airbus-iframe=true&airbus-post=2108) explicitly describes A330 speed-margin, ordering and runway-change checks. | General Airbus principles support checks, not a complete takeoff calculation. Exact A330-941/P5A alert thresholds, rounding and effectivity remain unverified. |
| Scalar interpolation, correct table endpoints and invalid-input handling | These correct software defects in the inherited speed lookup. Its minimum-control tables cite VIR A330-941 FCOM LIM-AG-SPD pages 3/4 in a source comment. | No revision or independently verified original table was available. Interpolation and holding the endpoint outside the table are implementation policies, not proven FCOM instructions. |
| SimBrief takeoff report import and runway selection | [Official OFP fetch API](https://developers.navigraph.com/docs/simbrief/fetching-ofp-data); [SimBrief staff confirmation of TLR export, March 2025](https://forum.navigraph.com/t/tlr-section-export-via-api/18898). | Results describe the generated OFP conditions. Import does not recalculate for actual weight, weather, configuration, runway intersection or aircraft modifications. Data must be checked against the intended departure. |
| Conservative report-unit labeling | [SimBrief staff's printed/XML comparison, September 2025](https://forum.navigraph.com/t/performance-data-calculation/20726) shows raw runway lengths in feet and raw pressure in inHg while printed pressure is hPa. [Distance selection is independent of weight units](https://forum.navigraph.com/t/ofp-take-off-landing-perf-units-always-in-feet/16822). The implementation labels mass from OFP units only when report TOW agrees with OFP TOW. | No complete public raw TLR unit schema was established. Unverified units must not be inferred from aircraft type or weight units. Original report text remains the reference. |
| STEP entries and F-PLN predictions | [Headwind's target configuration](https://github.com/headwindsim/aircraft) names A330-941 and Honeywell P5A, while noting that equipment may be implemented or only targeted. | No primary source established a ground-only rule showing cruise FL at every unconstrained enroute waypoint. That override was removed because it masked climb predictions before T/C. STEP entries are planning intent; they do not establish an instantaneous altitude change. |
| Invalid prediction handling | [Airbus Golden Rules, 2013](https://safetyfirst.airbus.com/app/themes/mh_newsdesk/documents/archives/the-golden-rules-for-pilots.pdf) requires monitoring targets, modes and aircraft response, and changing automation level when needed. | Rejecting impossible software results is an engineering check. It does not establish exact real-aircraft blanking, scratchpad messages or recovery behavior. Actual flight level and pilot FCU intent retain existing simulation behavior; this is not validation of a certified guidance standard. |
| Six-tank fuel and opt-in trim controller | See [references and assumptions](references-and-assumptions.md) for EASA capacity evidence, SDK semantics and inherited positions. | Direct center/trim topology, trim arm, valve behavior and transfer controls are experimental. Rate defaults to zero; no validated automatic neo CG schedule exists. This is not FCOM-compliant trim-system modeling. |

## Work that remains

A full native interactive A339 takeoff calculator remains incomplete. No usable, validated complete A339 performance model or supported standalone calculation service was established. Manufacturer airport-planning charts and inherited speed tables cannot alone establish FLEX, obstacle, accelerate-stop and configuration-dependent performance.

Deterministic tests, typechecks, builds and package checks validate defined software behavior. They do not establish real-aircraft performance, complete simulator integration or failure-free operation.

Remaining simulator scenarios include:

- KSEA runway 16L, 230.2 t, CONF 1, entered V1/VR/V2 148/155/161 kt: verify data entry, ordering/minimum checks, report context and displayed values. These are supplied test inputs, not independently validated takeoff results; weather, pressure, runway condition and thrust setting are still required for performance validation.
- A route with unconstrained enroute fixes before T/C, cruise fixes, a planned step and fixes beyond T/D: confirm climb and descent predictions remain visible, STEP edits update the plan, and FCU selections govern existing guidance behavior.
- Missing or impossible VNAV inputs followed by corrected inputs: confirm invalid results are not presented as valid predictions, constraints survive and predictions recover.
- Native fuel readback, density changes, trim power/failure/refuel inhibition, pause/resume, persistence and measured CG movement through a complete simulator flight.
